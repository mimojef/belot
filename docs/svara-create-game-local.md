Изходен HEAD: `d0fed77c105a47e99742d3d7d65e7e0e95b4e247`, клон `v2-clean-architecture`.
Само виртуален тестов режим. Този отчет описва локалния етап преди одобрението за commit/push от 19.10.2026 г.; описаното по-долу непубликувано Git състояние е историческо. Финалните проверки и настройките за друг компютър са в `docs/svara-waiting-table-local.md`.

## Поведение

- Прозорецът следва Ludo: черен фон, златен контур, ширина до 420 px, същите полета и 42 px контроли. Стандартен модален `dialog` го показва над мащабирания shell, така че landscape режимът не смалява формата. При нисък екран съдържанието се превърта вътре в прозореца.
- По подразбиране: 2 участници, вход 5000, „При запълване“.
- Входове: **5000, 8000, 15000, 20000, 35000, 50000, 60000, 80000, 100000, 130000, 150000, 180000, 200000**. Няма свободно въвеждане.
- Настройките се получават от защитения `GET /api/games/svara/access` след съществуващите session/role/feature проверки. При недостъпна/невалидна конфигурация няма активна форма за създаване; има „Отказ“ и повторна проверка.
- Новата сървърна политика допуска само тези входове и точно 1%. Подадени 5%, други проценти, низове и стойности извън списъка се отказват; липсващ процент се задава от сървъра като 1%.
- Стартови чипове = вход / 10; анте = стартови чипове / 100. Engine изчислява показваните стойности. Всички разрешени входове дават цели числа, без ново закръгляване.
- Сумите във формата използват установения в проекта `Intl.NumberFormat('bg-BG', { useGrouping: 'always' })` с неразривен интервал между хилядите. Числовите стойности в командите остават непроменени. Под входа е добавено „Получаваш: X виртуални чипа“, като X е сървърното `startingChips`; при вход 150 000 се показват 15 000 виртуални чипа и анте 150. Информацията се обновява веднага и е подредена с компактен интервал между редовете.
- Примери: 5000 → 500 чипа → анте 5; 8000 → 800 → 8; 15000 → 1500 → 15; 200000 → 20000 → 200.
- Визуална награда = вход × участници × 4 / 5. Текстът е „Изчислена тестова награда: X жълтици (не се изплаща)“. При вход 5000 и 2/3/4 участници: 8000/12000/16000.
- „При запълване“ използва съществуващия автоматичен старт; „Ръчен старт“ запазва изискването за пълна маса и старт само от създателя. Engine/lifecycle правилата за стартиране не са променяни.
- Формата запазва избора при обновяване и повторно монтиране на общия екран. Отказът не изпраща команда за създаване.
- Ограничението е за нови Свара маси. Съществуващи snapshot-и с друг вход или 5% анте се възстановяват без пренаписване.

Няма интеграция с реалните жълтици, удържане на входове, комисиона или реално изплащане. Формулата е само визуален разчет за бъдещо стандартно приключване с един победител. Профилните баланси, платежните ledgers, engine, игровите банки, карти, анимации и таймери не са променяни. Ludo запазва своя динамичен списък.

## Локален преглед

1. Отвори **http://localhost:5173/games/svara** и влез с локален профил с разрешена служебна роля, например съществуващия администратор `Mimojef`.
2. Презареди страницата, избери „Истинска игра“ и натисни „+ Създай игра“.
3. Провери стойностите по подразбиране, смени входа и броя участници и наблюдавай антето/тестовата награда. „Отказ“ затваря прозореца без създаване.
4. За игра са нужни независими разрешени профили в отделни браузърни профили/инкогнито контексти. При ръчен режим създателят натиска „Старт“ след запълване.
5. Ако се възстанови стар завършен резултат, затвори го с „Изход“, преди да създаваш нова маса.

Локалният `server/.env` остава игнориран от Git и съдържа `SVARA_TEST_ENABLED=1`. Той не отменя проверките за роли. HTTP/игровият WS използват порт 3001; Vite е на 5173. Не стартирай втори процес върху зает порт.

При следващо стартиране, в отделни PowerShell терминали:

```powershell
cd D:\Project\belot-v2\server
npm.cmd run dev
```

```powershell

```
